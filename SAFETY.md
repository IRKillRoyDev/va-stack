# Safety

- **Not legal or medical advice.** This project produces organized research notes only. It does not decide entitlement, predict ratings, or diagnose anything.
- **Verify with an accredited professional.** Before acting on any output, review it with a VA-accredited representative, a Veterans Service Organization (VSO), or a VA-accredited attorney or claims agent. Accreditation can be checked at https://www.va.gov/ogc/apps/accreditation/.
- **No filing.** The bot never submits, files, signs, or transmits a claim, form, or document to VA or anyone else. The user decides what, if anything, to file.
- **Where records go.** Record files are stored only in the folder the user chooses. The skills never commit, upload, or copy those files anywhere else. However, the text the bot reads from them is processed by the AI service the bot runs on, so it does leave the machine. Check that service's privacy terms before using real records. A fully offline setup needs a local model. To limit what is sent, the local-search skill runs `scripts/local_search.py` on the user's computer (no network calls, nothing written to disk) and returns capped, redacted snippets; the user approves the snippet list before any of it goes to the AI service, and whole pages are read only with explicit approval. Redaction is pattern-based and can miss things. Names are not automatically redacted, including third-party names; review each snippet before approving it. Redaction is pattern-based and can miss things in both directions: it can miss identifiers and it can over-redact ordinary numbers or dates. A bare year (for example "born in 1961") is not redacted.
- **Encrypted records vault (optional).** `scripts/records_vault.py` keeps records in a SQLCipher database on the user's computer, keyed with Argon2id from the user's password; the salt and Argon2id settings are stored unencrypted next to it in `<db>.kdf.json`. Every unlock shows a consent-to-share notice first and the password field stays disabled until the user consents; consent is never remembered. The password is typed locally and is never accepted as an argument or environment variable, printed, or logged. Every request must carry the requesting bot id, and an access log inside the encrypted file records the session, consent version, bot id, records searched, and each snippet sent (file, page, line, SHA-256 hash, never the text), hash-chained so edits or deletions are detected. At the end of a session the key buffer and password buffer are overwritten with zeros and the database is closed. Python cannot fully guarantee memory wiping: the password from the prompt and decrypted record text exist as immutable Python strings that cannot be overwritten, the garbage collector and libraries may keep copies, and the operating system may write memory to swap or crash dumps. Use full-disk encryption and close the program when done.
- **Primary sources only.** Every legal statement cites its primary source, fetched in the same session with an "as of" date: 38 CFR (eCFR API), the U.S. Code (govinfo), DoD instructions (official DoD issuances site), or live VA.gov pages. Nothing is cited from memory. If a fetch fails, the bot stops.
- **No guessing.** If evidence is missing or ambiguous, the bot says so and lists it as a gap.
- **Crisis support.** If you are a veteran in crisis, or worried about one, contact the Veterans Crisis Line: dial 988, then press 1 (or text 838255, or chat online). Sources, checked 2026-10-16: https://www.veteranscrisisline.net/ and https://www.va.gov/health-care/health-needs-conditions/mental-health/. If you are in immediate danger, call 911.
- **No real patient data in this repo.** Everything under `tests/` is fictional.
